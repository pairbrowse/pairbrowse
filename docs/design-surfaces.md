## Surfaces (Phase 1 map)

Six surfaces, one reader each. Nothing below was changed; this is the map the subsets build on. The logo (`scripts/browser/pairbrowse.icns`, `scripts/browser/product-icon.svg`, `scripts/browser/panel/logo.svg`, `panel/icon16/32/48/128.png`, the `SPARK` path in `hud.js:228` / `common.js:36`, the `CHROMIUM_LOGOS` swap in `scripts/macos-app.mjs:145-222`) is a fixed input on every surface.

Classification key: **EXISTS** (already there, where), **REFINE** (there, what changes), **NEW** (not there; where it lives and which existing state feeds it), **UNSUITABLE** (cannot be done from the plugin, or breaks a rule).

### 1. Chrome: the window itself

**What it is.** Tab strip, toolbar, omnibox, side panel host, window colors, new tab page, the toolbar action button and its shortcut, app name, icon and logo.

**Who renders it.** Chromium draws the frame; PairBrowse never draws window chrome. It shapes it in six ways: (1) profile prefs written before every launch, `prepareProfile()` at `scripts/browser.mjs:219-234`, called from `scripts/daemon/context.mjs:236`, `scripts/native-install.mjs:203`, `scripts/native-check.mjs:88`; it writes `Default/Preferences` through `profilePreferences()` (`browser.mjs:124-168`), fixes Secure Preferences through `profileSecurePreferences()` (`:176-192`), `acknowledgeNewTabPage()` (`:199-202`), `localStatePreferences()` (`:207-215`).
