## Surfaces (Phase 1 map)

Six surfaces, one reader each. Nothing below was changed; this is the map the subsets build on. The logo (`scripts/browser/pairbrowse.icns`, `scripts/browser/product-icon.svg`, `ui/logo.svg`, `ui/icon16/32/48/128.png`, the `SPARK` path in `scripts/hud/spark.js` / `ui/dom.js`, the `CHROMIUM_LOGOS` swap in `scripts/native/macos-app.mjs` `rebrandLogos()`) is a fixed input on every surface.

Classification key: **EXISTS** (already there, where), **REFINE** (there, what changes), **NEW** (not there; where it lives and which existing state feeds it), **UNSUITABLE** (cannot be done from the plugin, or breaks a rule).

### 1. Chrome: the window itself

**What it is.** Tab strip, toolbar, omnibox, side panel host, window colors, new tab page, the toolbar action button and its shortcut, app name, icon and logo.

**Who renders it.** Chromium draws the frame; PairBrowse never draws window chrome. It shapes it in six ways: (1) profile prefs written before every launch, `prepareProfile()` in `scripts/browser.mjs`, called from `scripts/daemon/browser/launch.mjs` `launch()`, `scripts/native/install.mjs` `installNative()`, `scripts/native/check.mjs` `selfCheck()`; it writes `Default/Preferences` through `profilePreferences()`, fixes Secure Preferences through `profileSecurePreferences()`, `acknowledgeNewTabPage()`, `localStatePreferences()` (all in `scripts/browser.mjs`). (2) Chromium's built-in color theme, not a theme extension: `THEME_COLOR = 0xff4e6498|0` in `scripts/browser.mjs`; `profilePreferences()` sets `extensions.theme={id:"user_color_theme_id"}` and `browser.theme={user_color2, color_variant2:1, color_scheme2:2, follows_system_colors:false}`, only when the user has not picked a theme; the old theme extension is migrated away (`OLD_THEME_DIR`, `isOldThemePath()`, `profilePreferences()`, `profileSecurePreferences()`). (3) Flags: `browserArgs()` in `scripts/browser.mjs` (`--disable-extensions-except/--load-extension=ui`; darwin only `--show-avatar-button=never`, first run `--no-startup-window`); `launchArgs()` (`--window-size=1366,900`, `--hide-crash-restore-bubble`, `--test-type`, backgrounding flags, `--allowlisted-extension-id`, one merged `--enable-features`, `config.chromeArgs`); `ignoreDefaultArgs ["--disable-extensions"]`, then in `context.mjs`, now `launchOptions()` in `scripts/browser.mjs`. (4) The one MV3 extension, `ui/manifest.json`: action (`default_title "PairBrowse"`, icon16/32), `side_panel.default_path panel.html`, `chrome_url_overrides.newtab newtab.html`, command `open-panel` (Cmd/Ctrl+Shift+Y); `ui/background.js`: its top-level `setPanelBehavior({openPanelOnActionClick:true})`, `sidePanel.open` in the `chrome.commands.onCommand` listener, the first window on a fresh macOS profile (the block on the `started` session key). (5) macOS bundle branding: `ensureBrowser()` in `scripts/browser.mjs`; native build `brandNativeApp()` plus `rebrandLogos()` in `scripts/native/macos-app.mjs`; `rebrandInterfaceText()/rebrandPak()` there too. (6) Native launch path `launchNative()` in `scripts/native-engine.mjs`, `splitExtensionArgs()`, engine switches inside `launchNative()`; none touch chrome.

**State source.** `Default/Preferences`, all from `profilePreferences()` in `scripts/browser.mjs` (`restore_on_startup=5`; pinned panel; `_execute_action` dropped; theme; quiet permission UI; battery saver off; NTP footer off; signin/default-browser/translate/credentials/autofill off), plus `ack_existing_ntp_extensions` (`acknowledgeNewTabPage()`). `Secure Preferences`: deletions only, with MACs (`profileSecurePreferences()`); PairBrowse cannot set values there (the comment above `acknowledgeNewTabPage()`). `Local State`: guest and add-person off, profile name "Your PairBrowse" (`localStatePreferences()`). Panel-build marker and Service Worker reset (`PANEL_BUILD_FILE`, `panelWorkerStale()`, `resetPanelWorker()`). Manifest key fixes the extension id (`panelExtensionId()`). Bundle stamp `'branding v6'` (`ensureBrowser()`); native `BRANDING=5` (`scripts/native/macos-app.mjs`; `scripts/native/install.mjs` `installNative()`, `rebrandInstalled()`, `ensureNativeBrowser()`). `config.json chromeArgs` (`launchArgs()` in `scripts/browser.mjs`; `docs/configuration.md`, the `chromeArgs` entry), `config.pairbrowse` (`readSettings()` in `scripts/native-engine.mjs`).

**Update mechanism.** None live. Written once before each launch (`launch()` in `scripts/daemon/browser/launch.mjs`); Chromium reads prefs at startup only, so theme, pins and flags change on the next browser start. Branding once per build (stamp in `ensureBrowser()` in `scripts/browser.mjs`; native `ensureNativeBrowser()` in `scripts/native/install.mjs`). No polling.

**Styling.** One seed color, `THEME_COLOR 0xFF4E6498` (`scripts/browser.mjs`), variant 1 "tonal", scheme dark; Chromium derives all tab strip, toolbar and omnibox colors from it. No CSS, no tokens, no font for the frame. New tab page: `newtab.html` (logo.svg 96px, h1, search input), `newtab.css` (`#141838` + `ntp.png` cover, text `oklch(0.97 0.01 265)`, frosted pill `backdrop-filter blur(20px)`, focus `oklch(0.84 0.12 215)`, system-ui 15px), `newtab.js` (`addressToUrl`; only http(s) opens, the `submit` listener in `ui/newtab/newtab.js`); `ui/newtab/index.html` `<meta name="color-scheme">` `color-scheme dark`.

**Controls.** Pinned action button (`profilePreferences()` in `scripts/browser.mjs`; the `setPanelBehavior` call in `ui/background.js`); `open-panel` command (`manifest.json commands`; the `chrome.commands.onCommand` listener in `ui/background.js`; old binding removed in `profilePreferences()`); side panel host; new tab override; avatar hidden on macOS only (`browserArgs()`), guest/add person removed everywhere (`localStatePreferences()`); quiet permission icons (`profilePreferences()`); suppressed bubbles and infobars (`launchArgs()`, the header comment of `scripts/browser.mjs`, `profilePreferences()`); window size 1366x900 (`launchArgs()`).

**Constraints.** The seed color is the only lever on the frame (`THEME_COLOR`, `profilePreferences()` in `scripts/browser.mjs`); a theme extension would break `checkProfile()` in `scripts/native/check.mjs` and `test/browser.test.mjs` test "profiles get Chromium's own navy color theme instead of the old theme extension". Secure Preferences is MAC-sealed (`profileSecurePreferences()`, the comment above `acknowledgeNewTabPage()`). Only one extension may load (`browserArgs()`; `checkProfile()` in `scripts/native/check.mjs`; `test/browser.test.mjs` test "the browser loads only the side panel extension"). `--show-avatar-button` is darwin only (`browserArgs()`); Linux/Windows run Playwright's Chromium (`ensureBrowser()`) with the profile button. App name, icon, bundle id change on macOS only (`ensureBrowser()`; `brandNativeApp()` in `scripts/native/macos-app.mjs`); pak rewriting handles format 5 only (`rewritePak()`, `rebrandPak()` in `scripts/native/macos-app.mjs`); copyright strings and project link must stay (`PROJECT_LINK`, `brandText()`; `test/native-install.test.mjs` test "Chromium keeps its credit: copyright strings and the link to its project"). `rebrandLogos` is native only and hash-matched per Chromium version (`CHROMIUM_LOGOS`, `brandNativeApp()` in `scripts/native/macos-app.mjs`). Native build passes `launchArgs` through unchanged except extension switches (`splitExtensionArgs()`, `launchNative()` in `scripts/native-engine.mjs`; its `pack.gateEngineSwitches()` call); its own chrome is decided in `../pairbrowse-native`. No TCP debugging port (pipe, the header comment of `scripts/browser.mjs`); `--allowlisted-extension-id` gives tab capture to the panel only (`launchArgs()`); `docs/security.md` changes with any of these. Backgrounding flags and `ForceForegroundPriorityForAllTabs` keep the live view rendering (`FEATURES`, `launchArgs()` in `scripts/browser.mjs`); one merged `--enable-features` (`FEATURES`, `ENABLE`; `test/browser.test.mjs` test "hidden tabs keep foreground priority, in one --enable-features that keeps the driver's"). `restore_on_startup=5` is required (`profilePreferences()`). Theme pref keys are cited from Chromium 150 `pref_names.h` (the comment on `THEME_COLOR`) against pin `154.0.8037.57-1.1` (`UNGOOGLED`): re-verify before changing them. `docs/security.md` mentions none of theme, toolbar or avatar, so a chrome-only color change needs no table edit unless flags or extension permissions change.

**Tests.** `test/browser.test.mjs` tests "Chromium's interface text is renamed to PairBrowse, web addresses stay" and "other pak formats are left alone" (rebrandPak), "the side panel's id comes from its manifest key like Chromium does, wherever the folder is" (id from key), "earlier copies' path-derived side panel records and buttons are removed", "profiles get Chromium's own navy color theme instead of the old theme extension", "the browser loads only the side panel extension", "a disabled side panel record is dropped so Chromium loads it enabled again", "the old theme extension is recognized wherever that copy of PairBrowse lived", "prepareProfile writes Preferences and rewrites Secure Preferences only when needed", "site notification and location requests are quiet, not denied", "a profile's default name says PairBrowse;
